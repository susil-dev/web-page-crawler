# Table Scrapers Dominate, Site Crawlers Stay Rare

The Chrome Web Store scraper market belongs to two free tools that turn one page into a spreadsheet. **Instant Data Scraper has about 1M users and a 4.9 rating**, and **Web Scraper (webscraper.io) has about 900K users and a 4.7 rating**. Behind them sit freemium tools (Data Miner, Table Capture, Agenty, Listly, Easy Scraper, Simplescraper) and a newer group of AI scrapers billed by credits (Thunderbit, Browse AI, Bardeen, Axiom). On GitHub, the activity has moved away from extensions altogether. Server-side engines now lead on stars: **Firecrawl (~209k), browser-use (~122k), Scrapling (~106k) and Crawl4AI (~88k)** have all passed Scrapy (~66k). Their selling points are LLM-ready Markdown, schema or prompt extraction, and MCP servers. Open-source *extensions* are mostly clippers and archivers (SingleFile, Obsidian Web Clipper, ArchiveWeb.page) or automation tools (Automa, Nanobrowser). Only a handful of small projects actually crawl multiple pages. That leaves a clear gap: **no popular, maintained extension combines a same-site multi-level crawl with clean Markdown export, local-only storage and documented crawl controls such as depth, scope and robots.txt**. Those features exist only in server-side frameworks. Pricing complaints dominate reviews of the AI and freemium tools, which means a free, local, bring-your-own-key design addresses the category's most common grievance. The rest of this report maps the landscape so a builder of a Page Crawler extension can see where it fits.

## Two free table scrapers own the Chrome Web Store, and paywalls cost ratings

The classic extensions share one model: open a list or table page, detect the repeating items, page through them, and export CSV or XLSX. The leaders differ in how much control they give. Instant Data Scraper auto-detects the main list or table, waits for dynamic content with a configurable delay, follows next buttons and infinite scroll, and exports to Excel or CSV. It does not follow links to detail pages, schedule runs or use a cloud ([CWS](https://chromewebstore.google.com/detail/instant-data-scraper/ofaokhiedipichpaobibbnahnkdoiiah); [webscraper.io blog](https://webscraper.io/blog/web-scraper-vs-instant-data-scraper)). Web Scraper is the power tool. It uses a "sitemap" tree of typed selectors (Text, Image, Table, Link, Pagination, Sitemap.xml Link, Element click), each with its own delay, and adds an AI Sitemap Wizard and Website State Setup for logins ([selector docs](https://webscraper.io/documentation/selectors)). Its paid cloud adds cron scheduling, an API, data-quality alerts, proxies and exports to S3, Drive and Sheets, starting at **$50/month for 5,000 page loads** ([pricing](https://webscraper.io/pricing)).

## AI scraper extensions sell credits, and the credits draw the complaints

A second group puts an LLM in the setup step: describe the columns, or let the AI suggest them, then enrich each row from its subpage. **Thunderbit**, the most-cited AI-first extension, has about 100K users and a **3.9 rating**. It offers AI-suggested columns, subpage enrichment, pagination, scheduling, monitoring, PDF and OCR extraction, and exports to Sheets, Airtable and Notion. Its free plan covers just 6 pages a month, and paid plans run $15–$38/month on credits metered by output rows ([CWS](https://chromewebstore.google.com/detail/thunderbit-ai-web-scraper/hbkblmodhbmcakopmmfbaopfckopccgp?hl=en); [whatallsay](https://www.whatallsay.com/thunderbit-review/)). The other big names use the extension mainly as a recorder or trigger for a cloud product. Browse AI trains cloud "robots" for monitoring and sells credits where one credit is roughly 10 rows, and unused credits reset each cycle ([tomba.io](https://tomba.io/blog/browse-ai-pricing-reviews-pros-and-cons)). Bardeen bundles scraping into sales automation and runs only while the browser is open ([automationatlas](https://automationatlas.io/answers/bardeen-review-2026/)). Axiom.ai (about 100K users, 4.5 rating) bills by runtime hours ([CWS reviews](https://chromewebstore.google.com/detail/cpgamigjcbffkaiciiepndmonbfdimbb/reviews?hl=en); [toolradar](https://toolradar.com/tools/axiom-ai)). Gumloop records and replays actions ([CWS](https://chromewebstore.google.com/detail/gumloop/hpkeijgchoedhhdfjdjlaimanpmbnhjm)), and Kadoa requires an account login ([CWS](https://chromewebstore.google.com/detail/kadoa-ai-web-scraper/nmmlhnjgcechchnkjpkofkjemmlfbnnd)).

Complaints about cost are consistent. Capterra reviewers say Thunderbit's "free plan credits run out fast and the paid plans get expensive" ([Capterra](https://www.capterra.com/p/10027321/Thunderbit/)). A Trustpilot reviewer calls Bardeen "no transparency, no control, and outrageous costs" ([Trustpilot](https://ca.trustpilot.com/review/bardeen.ai)). Browse AI's monitoring "quietly burns credits" ([dailyaifixs](https://dailyaifixs.com/blog/browse-ai-pricing-2026-the-credit-reset-catch)). Reliability gets complaints too: AI output "still needs validation" ([webscraper.io blog](https://webscraper.io/blog/best-web-scraping-browser-extensions)). The LLM-oriented Markdown niche, meanwhile, lives in separate single-page clippers, and the store listing of one of them notes that "formerly-popular markdown clippers have gone unmaintained" ([CWS](https://chromewebstore.google.com/detail/page-to-markdown-for-llms/odobeannfnpgmcokfaneihlpjppcgeni)). No official Firecrawl, Jina, Apify or Octoparse extension turned up. The only Firecrawl extension found is the third-party Fireclaw (about 300 users), which needs the user's own Firecrawl API key ([CWS](https://chromewebstore.google.com/detail/ijbiocoljkhbnjgjajpbjkfnagakbjjm)). Most comparison articles in this space are written by competing vendors, so their rankings deserve skepticism.

## Open-source extensions clip and archive far more than they crawl

The open-source extension landscape is lopsided. Large, active projects capture a single page or automate a browser. Multi-page crawlers are tiny or dead. The webscraper.io codebase went proprietary. Its old open code survives as the **abandoned MV2 repo (1,363 stars, last push 2018)** and as the **ispras MV3 fork (288 stars, LGPL-3.0, active April 2026)**. The ispras fork is the richest open-source crawler extension. It has typed selectors, click and scroll-down selectors for dynamic pages, a pagination limit, URL range patterns, random and per-visit delays, regex post-processing and CSV/JSON Lines export ([ispras README](https://github.com/ispras/web-scraper-chrome-extension)). No open-source clone of Instant Data Scraper was found.

moe-copy-ai is the closest functional neighbor to a page-crawler-plus-Markdown extension. It collects links from a page region, filters them by domain or regex, follows next buttons, and fetches each document via the **Fetch API, a background tab or the current tab**. It outputs HTML, Markdown or text with token counts and exports a ZIP. Its AGPL license, though, rules out reusing its code in a permissively licensed project ([README](https://github.com/yusixian/moe-copy-ai)). Site-Viewer crawls a whole site and reports broken links, but it documents no depth limits or throttling ([README](https://github.com/Bimmr/Site-Viewer)). **None of the reviewed extension READMEs documents robots.txt handling, crawl-depth limits or same-origin enforcement.** The permissive building blocks are well established: **defuddle (10.2k stars, MIT)**, **Mozilla Readability (11.6k, Apache-2.0)**, **Turndown (11.5k, MIT)** and **selectorgadget (1.1k, MIT)** for point-and-click selector generation ([defuddle](https://github.com/kepano/defuddle); [readability](https://github.com/mozilla/readability); [turndown](https://github.com/mixmark-io/turndown); [selectorgadget](https://github.com/cantino/selectorgadget)). Star counts say little about maintenance here: the 2-star scrape-similar is far more alive than the 1.3k-star original Web Scraper repo.

Manifest V3 shapes what these projects can do. Chrome kills an extension service worker **after 30 seconds idle, after 5 minutes on one event, or when a fetch response takes over 30 seconds** ([Chrome docs](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)). Crawl state therefore has to live in `chrome.storage` or IndexedDB rather than in memory, and HTML fetched in a worker has to be parsed in a single offscreen document (`DOM_PARSER`), because workers have no DOM ([offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen)). The MV2-to-MV3 port has already stranded MarkDownload and the original Web Scraper.

## Server-side frameworks set the crawl and LLM bar extensions have not reached

Frameworks are where crawl control and LLM output both reach full depth. Classic engines handle the plumbing. **Scrapy** provides robots.txt, depth limits, AutoThrottle, per-domain concurrency, a sitemap spider and JSON/CSV/XML feed exports ([docs](https://docs.scrapy.org/en/latest/intro/overview.html)). **Crawlee** offers HTTP and headless crawling through one interface, a persistent queue, resource-based autoscaling, and TLS and browser fingerprinting ([README](https://github.com/apify/crawlee)). **Colly**, **Katana** and **spider-rs** cover the same ground in Go and Rust. spider-rs's `crawl_smart()` runs HTTP first and switches to Chrome only when a page needs JavaScript ([README](https://github.com/spider-rs/spider)). The AI-era engines add the output layer. **Crawl4AI** has "Fit Markdown" with BM25 and LLM filters, an LLM that writes a reusable CSS schema once, BFS/DFS/best-first deep crawls with crash recovery, and an AdaptiveCrawler that stops once it has enough information ([README](https://github.com/unclecode/crawl4ai)). **Firecrawl** offers Scrape, Crawl, Map, Search, Agent and Monitor endpoints. Its local mode writes one Markdown file per page and registers itself as an MCP server in Claude Code and Cursor ([README](https://github.com/firecrawl/firecrawl)). **Scrapling** combines stealth fetchers, Scrapy-style spiders with optional robots.txt compliance, "adaptive" selectors that relocate elements after redesigns, whole-site Markdown and MCP ([README](https://github.com/D4Vinci/Scrapling)). **Jina Reader** adds token budgets (`x-max-tokens`) and render-timing controls ([README](https://github.com/jina-ai/reader)).

Most of these tools follow an **open-core model**: an AGPL or MIT repo, with stealth proxies, agents, search and monitoring held back for a paid cloud. Treat the AI repos' star counts as a popularity signal rather than evidence of production use. Scrapling went from about 59k stars in June 2026 to 105k by late November ([Star History](https://www.star-history.com/d4vinci/scrapling/)), the kind of curve trending dynamics produce. The framework landscape defines what a crawler is now expected to do: depth and scope control, throttling, robots.txt, sitemaps, clean Markdown, schema extraction and an agent hook. No extension listed earlier delivers that combination.

## Where a local, site-walking Markdown crawler fits

The Page Crawler & Summarizer extension in this repository (MV3, `activeTab`, `scripting`, `storage`, `unlimitedStorage`, `downloads`) already sits in the gap identified above. It crawls a link tree from the current page up to five levels deep. It converts pages to Markdown with Readability and Turndown and stores them in local IndexedDB. It fetches pages over HTTP first and falls back to a rendered background tab when the result is under 40 words or refused, the same smart escalation spider-rs and Crawlee use server-side. It detects duplicate pages through redirects, canonical URLs and content, and sends data only to the Claude API, using the user's own key. Mapped against the landscape, the open opportunities look like this.

| Opportunity | Who has it today | Status in this extension (per README) |
|---|---|---|
| Multi-level same-site crawl tree in an extension | Server frameworks; Site-Viewer (5 stars), moe-copy-ai (AGPL) | Has it (depth 1–5, max pages) |
| Markdown export of crawled pages | Clippers (single page only); Firecrawl/Crawl4AI server-side | Has it (.md with front matter, image folders) |
| Local-only storage, no account | Instant Data Scraper, markdown clippers | Has it (IndexedDB); differentiates against Thunderbit, Browse AI, Kadoa |
| Bring-your-own-key AI | Fireclaw (Firecrawl key) | Has it (Anthropic key) |
| HTTP-first, render-on-demand fetching | spider-rs, Crawlee, Jina, moe-copy-ai | Has it (Automatic mode, ≤2 tabs) |
| robots.txt, crawl-delay, sitemap.xml seeding | Scrapy, Colly, Scrapling, spider-rs; no extension documents it | Missing ("Doesn't read robots.txt") |
| URL include/exclude patterns and scope rules | Katana, moe-copy-ai, Scrapling LinkExtractor | Not documented |
| Structured field extraction (selectors or LLM schema) | Web Scraper, Crawl4AI `generate_schema`, Stagehand | Missing; summaries only |

| Token-budgeted or filtered "fit" Markdown | Crawl4AI, Jina Reader | Missing |

| MCP or agent access to the saved library | Firecrawl, Crawl4AI, Scrapling, Simplescraper | Missing |
| Change monitoring / scheduled re-crawl | Browse AI, Firecrawl Monitor, changedetection.io (all cloud) | Missing; `chrome.alarms` makes a local version feasible |

The strongest openings combine what the extension already does with what only servers do today. Adding robots.txt and crawl-delay compliance, sitemap.xml seeding, and include/exclude URL patterns would make it the first extension to document classic crawl etiquette, a gap the open-source review found in every README. A Crawl4AI-style "write the schema once with Claude, then extract without the LLM" step would bridge the AI table scrapers and the Markdown clippers, giving users structured CSV output without per-row credit costs. Exposing the IndexedDB library to agents through MCP, or a native-messaging bridge, would follow the clearest framework trend; none of the reviewed extensions besides Simplescraper's cloud offers it. Prompt-injection risk from page content sent to an LLM is worth handling explicitly, since web2md already warns about it ([web2md](https://github.com/the-code-rider/web2md)).

## Conclusion

The landscape splits along a line that has little to do with how good the scraping is. Extensions became spreadsheet makers for one page plus its detail pages, monetized through quotas or cloud credits. Crawling whole sites into clean Markdown moved to server engines whose best features sit behind hosted plans. As a result, the most-requested modern capability, turning a site into LLM-ready text, is today available only on someone else's server or one page at a time. An in-browser crawler has a structural advantage that none of these servers can copy: it runs inside the user's own signed-in session with no proxies, accounts or data leaving the machine. That matters most for internal and corporate sites, where cloud tools cannot reach and users will not send content anyway.

The main uncertainty is demand rather than supply. The evidence on pricing complaints is consistent, but no review text confirmed that users want site-wide Markdown crawls from an extension specifically, and star counts for AI tools overstate real usage. The defensible position is therefore not "another AI scraper". It is a polite, local, resumable site crawler that produces the formats the AI ecosystem expects, Markdown, schema-extracted tables and an agent hook, with no meter attached. A builder can confirm or refute that thesis quickly by watching whether users ask for structured export or for MCP access first.
